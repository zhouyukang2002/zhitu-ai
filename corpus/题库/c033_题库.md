## q_c033_01
- type: choice
- kp: NumPy 数组
- difficulty: easy
- score: 5
- stem: NumPy 向量化运算快于 Python 循环的根本原因是？
- options: A) 代码更短 B) 底层 C 实现 + 连续内存批量运算，避免逐元素解释开销 C) GPU 加速 D) 自动并行

## q_c033_14
- type: short
- kp: 分组聚合

- stem: 【面试题】groupby 的 split-apply-combine 是什么意思？举例说明。
- keywords: 拆分, 应用, 合并, 聚合, 转换
- analysis: Pandas 分组运算的三阶段：split 按 key 拆成多组；apply 对每组独立应用聚合（sum/mean）、转换（transform 归一化）或过滤（filter）；combine 把结果按 key 合并回一张表。例：按城市拆分 → 各组计算客单价均值 → 合并成城市客单价表。理解该模型可举一反三使用 agg/transform/filter 三件套。

## q_c033_16
- type: short
- kp: Pandas 数据结构
- difficulty: medium
- score: 10
- stem: 为什么数据分析中要尽量避免"循环逐行处理 DataFrame"？替代方案是什么？
- keywords: 向量化, iterrows, apply, 性能, 内置方法
- analysis: 逐行 iterrows 每行都要构造 Series（对象开销大），比向量化慢百倍以上。替代：优先内置向量化方法（sum/mean/str 访问器）、条件逻辑用 np.where/np.select、跨列计算直接列运算；确实无法向量化的用 apply（仍是逐行但更整洁）或 swifter 加速。原则：先向量化，再 apply，最后才考虑循环。

## q_c033_18
- type: short
- kp: 分组聚合
- difficulty: medium
- score: 10
- stem: transform 与 agg 在 groupby 中的区别是什么？
- keywords: 返回形状, 聚合标量, 同形状转换, 排名占比, 组内均值
- analysis: agg 对每组返回一个聚合值（结果行数=组数）；transform 对每组返回与原行数相同的结果（组内广播），常用于"组内均值填充""组内标准化""计算每行占组内总和比例"。例：df['city_share'] = df['amount'] / df.groupby('city')['amount'].transform('sum')。
