## q_c005_01

- stem: HTTP 状态码 404 表示？

## q_c005_02
- type: choice
- kp: HTTP 与 Servlet
- difficulty: easy
- score: 5
- stem: GET 与 POST 请求的本质区别是？
- options: A) GET 不能传参数 B) GET 参数在 URL 上有长度与缓存语义差异，POST 参数在请求体 C) POST 一定更安全 D) GET 只能用于静态资源
- answer: B

## q_c005_03
- type: choice
- kp: HTTP 与 Servlet
- difficulty: medium
- score: 5
- stem: Servlet 是单例多线程的，因此 Servlet 中？
- options: A) 必须避免使用可变的实例成员变量 B) 不能有成员变量 C) 每个请求创建一个 Servlet 对象 D) init 方法每个请求执行一次
- answer: A
- analysis: Servlet 容器默认只创建一个实例，多个请求线程并发调用同一实例的 service 方法，可变的实例成员变量会出现线程安全问题，应使用局部变量或加锁。init 只在初始化时执行一次。

## q_c005_09

- options: A) 完全独立没有关系 B) Session 数据存服务端，通常依赖 Cookie 中的 JSESSIONID 识别用户 C) Cookie 存服务端 D) Session 更容易被伪造

## q_c005_10
- type: choice
- kp: 会话与 Cookie

- score: 5
- stem: 分布式多实例部署下，本机 Session 无法共享，常见的解决方案是？
- options: A) 每台机器重复登录即可 B) 用 Redis 集中存储会话（Spring Session） C) 把会话写进数据库主键 D) 关闭负载均衡

## q_c005_16
- type: short
- kp: 面试
- difficulty: hard
- score: 10
- stem: 【面试题】Cookie、Session、Token（JWT）三种会话方案的优缺点对比。
- keywords: 服务端存储, 无状态, 水平扩展, 签名, 过期时间
- analysis: Cookie：数据存客户端，容量小、可被用户查看篡改，适合非敏感偏好数据。Session：存服务端更安全，但占服务端内存且分布式需共享（Redis）。JWT：令牌含用户信息+签名，服务端无状态、易水平扩展；缺点是签发后无法主动作废（需黑名单机制）、载荷增加传输量。选型：单应用可用 Session；分布式优先 JWT 或 Spring Session + Redis。

## q_c005_17
- type: short
- kp: 面试
- difficulty: hard
- score: 10
- stem: 【面试题】拦截器（Interceptor）与过滤器（Filter）的区别？登录校验应该放在哪一层？
- keywords: 容器, Spring 上下文, 执行时机, 依赖注入, 前置处理
- analysis: Filter 是 Servlet 规范组件，由容器管理，拦截所有请求（含静态资源），早于 Servlet 执行，无法直接注入 Spring Bean（可间接获取）；Interceptor 是 Spring MVC 机制，只拦截进入 Controller 的请求，可以注入 Spring Bean、获取 Handler 信息。登录鉴权推荐用拦截器（能拿到注解/方法元数据，且不影响静态资源）；跨域、编码、全站安全头等容器级处理用 Filter。

- stem: @Controller 与 @RestController 的区别？返回 JSON 数据需要注意什么？
- keywords: ResponseBody, 序列化, 消息转换器, 视图, 统一响应

## q_c005_19
- type: short
- kp: MVC 分层
- difficulty: medium
- score: 10
- stem: 为什么 Controller 层不应该直接写业务逻辑和 SQL？说明分层的好处。
- keywords: 职责单一, 事务, 复用, 可测试性, 解耦
- analysis: 1) 职责单一：Controller 只做协议适配与参数校验，Service 承载业务规则与事务边界，DAO 只管数据访问；2) 复用：同一 Service 可被 Controller、定时任务、消息消费者共同调用；3) 可测试：业务逻辑不依赖 HTTP 环境即可单元测试；4) 解耦：更换协议（HTTP→RPC）或存储时上层不受影响。违反分层会导致事务失效、逻辑重复、测试困难。

## q_c005_20
- type: short
- kp: 面试
- difficulty: hard
- score: 10
- stem: 【面试题】如何设计一个统一的接口鉴权与参数校验方案（拦截器 + 校验注解 + 全局异常）？
- keywords: HandlerInterceptor, @Valid, BindingResult, ControllerAdvice, 统一响应
- analysis: 鉴权：HandlerInterceptor 从请求头取令牌校验，通过后将用户信息放入 ThreadLocal 供后续使用，未通过直接返回 401；白名单路径配置化。参数校验：DTO 上用 @NotNull/@Size 等校验注解，Controller 参数加 @Valid 触发。异常：@RestControllerAdvice 全局捕获 MethodArgumentNotValidException 与业务异常，统一转换为 {code, message, data} 响应结构。三层各司其职，业务代码零样板。
