## q_c022_01
- type: choice
- kp: Vue3 响应式
- difficulty: medium
- score: 5
- stem: Vue3 响应式从 Object.defineProperty 改为 Proxy 的核心收益是？
- options: A) 性能必然快十倍 B) 可拦截属性新增/删除与数组索引修改，无需 $set 等特判 API C) 兼容 IE D) 语法更简单
- answer: B
- analysis: Proxy 代理整个对象，拦截 13 种操作（含新增/删除属性、数组索引），解决了 Vue2 的三大痛点：新增属性不响应、数组索引赋值不响应、初始化递归遍历开销。

## q_c022_02
- type: choice
- kp: Vue3 响应式
- difficulty: medium
- score: 5
- stem: ref 与 reactive 的使用区别，正确的是？
- options: A) 完全等价 B) ref 包装基础类型/对象并通过 .value 访问，reactive 只用于对象且解构会丢失响应 C) reactive 用于基础类型 D) ref 不能存对象
- answer: B
- analysis: ref 内部用 RefImpl 包装（.value 触发依赖），reactive 用 Proxy 代理对象。reactive 的坑：解构/重新赋值丢响应，故组合式函数返回优先用 ref 或 toRefs 保持响应。

## q_c022_03
- type: choice
- kp: Vue3 响应式
- difficulty: hard
- score: 5
- stem: computed 与 watch 的选型原则是？
- options: A) 完全等价 B) computed 用于"派生值"（有返回、可缓存），watch 用于"响应变化执行副作用"（请求/操作 DOM） C) watch 性能更好所以全用 watch D) computed 不能依赖 store
- answer: B
- analysis: 派生数据用 computed（依赖不变则返回缓存值）；副作用（发请求、写 storage、操作非响应式库）用 watch/watchEffect。watchEffect 立即执行并自动收集依赖，watch 可指定来源与惰性执行。

- keywords: track, trigger, effect, 依赖收集, 调度

- keywords: Proxy, 组合式 API, 性能, TS 支持, 多根节点
