## q_c021_01
- type: choice
- kp: TS 类型系统
- difficulty: easy
- score: 5
- stem: TypeScript 是什么类型的语言？
- options: A) 强类型运行时语言 B) JS 超集，编译期为 JS 增加静态类型检查 C) 全新虚拟机语言 D) CSS 预处理器

- stem: 【面试题】为什么说"类型是给编译器看的，运行时会被擦除"？这对前端工程意味着什么？
- keywords: 编译期检查, 运行时校验, 外部数据, 契约, zod

- stem: 【面试题】解释条件类型与 infer：实现工具类型 UnwrapPromise<T> = T extends Promise<infer U> ? U : T。
- keywords: 条件类型, infer 推断, 递归, 分布式条件类型, 深层解包
- analysis: 条件类型 T extends X ? A : B 按类型关系分支；infer 在 extends 子句中"占位推断"内层类型，UnwrapPromise 把 Promise<number> 解包为 number。加递归可深层解包：T extends Promise<infer U> ? UnwrapPromise<U> : T。联合类型传入时条件类型分布式展开（每成员独立判断）。掌握条件类型是读懂高级工具类型（Partial 的映射实现）的基础。

## q_c021_15
- type: short
- kp: 类型收窄
- difficulty: medium
- score: 10
- stem: 什么是类型守卫（Type Guard）？手写一个判断"响应是否为错误结构"的守卫。
- keywords: is 谓词, 收窄, 结构判断, 联合类型, 运行时
- analysis: 类型守卫是返回值为 `arg is Type` 谓词的函数，运行时做结构判断，TS 据此收窄。示例：function isErr(r: unknown): r is { code: number; msg: string } { return typeof r === 'object' && r !== null && 'code' in r && 'msg' in r; }。调用后 if (isErr(res)) 分支内 res 即为错误结构类型——把运行时判断与编译期类型联动。

## q_c021_18
- type: short
- kp: TS 类型系统
- difficulty: medium
- score: 10
- stem: 结构化类型（鸭子类型）是什么？它与名义类型的差异带来什么好处与风险？
- keywords: 结构兼容, 形状, 误兼容, 品牌类型, 灵活性
- analysis: TS 按结构判断兼容：只要形状匹配即视为同类型，不管声明来源。好处：无需显式实现接口、第三方对象天然兼容。风险：两个语义不同但形状相同的类型可互相赋值（如 UserId 与 OrderId 都是 string）造成错用。解法：品牌类型 type UserId = string & { __brand: 'UserId' }，在类型层区分同名形状。

## q_c021_20
- type: short
- kp: 面试
- difficulty: hard
- score: 10
- stem: 【面试题】TS 在大型项目中的真正收益是什么？什么场景反而"不值得上 TS"？
- keywords: 重构安全, 协作契约, 补全, 小脚本, 维护周期
- analysis: 收益：1) 重构安全（改名/改字段编译期暴露所有引用）；2) 协作契约（模块边界即文档，补全即说明）；3) 把运行时低级错误前移到编译期。不值得的场景：生命周期极短的小脚本、原型验证期（类型维护成本 > 收益）、纯静态展示页。判断标准：维护周期与协作人数——维护越久、人越多，TS 收益越大。
