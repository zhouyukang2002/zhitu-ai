## q_c011_12

- options: A) 完全相同 B) Minor GC 回收新生代快而频繁，Full GC 整堆+元空间慢而代价高 C) Full GC 只回收新生代 D) Minor GC 更慢

## q_c011_13
- type: short
- kp: 垃圾回收
- difficulty: hard
- score: 10
- stem: 【面试题】简述 G1 收集器的回收流程与"可预测停顿"的实现原理。
- keywords: Region, Mixed GC, 停顿预测模型, SATB, Remembered Set
- analysis: G1 流程：1) 新生代 GC（Eden 满，存活对象复制到 Survivor/Old）；2) 并发标记周期（初始标记-并发标记-最终标记-清理，SATB 记录并发期引用变化）；3) Mixed GC：按停顿预测模型挑"回收价值最高"的老年代 Region 与新生代一起收集。可预测停顿：G1 统计各 Region 回收成本（存活对象/引用密度），每次只回收满足 MaxGCPauseMillis 预算的 Region 集合，把停顿控制在目标内。

## q_c011_16
- type: short
- kp: GC 调优
- difficulty: hard
- score: 10
- stem: 【面试题】-Xms 与 -Xmx 设置成相同值的好处是什么？G1 下 MaxGCPauseMillis 设得过小会怎样？
- keywords: 抖动, 预分配, 停顿目标, 吞吐, 换取
- analysis: Xms=Xmx：堆大小固定，避免运行期动态扩缩容带来的 GC 抖动与内存重分配，生产推荐。MaxGCPauseMillis 过小（如 5ms）：G1 为达标会缩小每轮回收的 Region 数、更频繁触发并发周期，年轻代也被压缩导致 Minor GC 更频繁——停顿目标与吞吐是权衡关系，设得过于激进会牺牲吞吐甚至无法达标，一般 200ms 以内按业务延迟要求设定。

- keywords: 逃逸分析, 栈上分配, 标量替换, 锁消除, 局部变量

## q_c011_18
- type: short
- kp: 面试
- difficulty: hard
- score: 10
- stem: 【面试题】ThreadLocal 为什么会导致内存泄漏？JDK 做了什么缓解？正确使用姿势是什么？
- keywords: 弱引用, Entry, remove, 线程池, value 强引用
- analysis: ThreadLocalMap 的 key 是弱引用（GC 后 key 为 null），但 value 是强引用且被线程的 ThreadLocalMap 持有——线程池中线程长期存活，value 无法回收造成泄漏。JDK 缓解：get/set 时探测并清理 stale entry，但不彻底。正确姿势：线程池场景用完必须 remove()（try/finally），并避免在 ThreadLocal 中放大对象。

## q_c011_20
- type: short
- kp: 面试
- difficulty: hard
- score: 10
- stem: 【面试题】对象什么时候会进入老年代？列举至少四种情况。
- keywords: 年龄阈值, 大对象, 动态年龄, Survivor, 空间担保
- analysis: 1) 年龄达到阈值（默认 15，MaxTenuringThreshold）；2) 大对象直接进入老年代（超过 PretenureSizeThreshold 或 G1 的 Humongous 区域）；3) 动态年龄判定：Survivor 中同龄对象总大小超过 Survivor 一半，大于等于该年龄的直接晋升；4) Minor GC 后 Survivor 放不下的存活对象经空间担保进入老年代。调优意义：过早晋升会加重老年代压力引发频繁 Full GC。
