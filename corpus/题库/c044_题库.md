## q_c044_01
- type: choice
- kp: Function Calling
- difficulty: easy
- score: 5
- stem: Function Calling 的本质是？
- options: A) 模型直接执行代码 B) 模型输出"要调用哪个工具与参数"的结构化决策，执行由应用完成 C) 数据库调用 D) 网页搜索
- answer: B
- analysis: 模型只做"选择工具+生成参数"的结构化推理，工具的真正执行、结果回填由应用编排——执行权始终在应用侧，这是安全的基石。

## q_c044_08
- type: choice
- kp: Agent 编排
- difficulty: hard
- score: 5
- stem: "LLM 提议计划，代码裁决"的编排设计中，代码层裁决的价值是？
- options: A) 没有价值 B) LLM 输出有不确定性，代码层校验（允许集合/状态机/上限）保证计划可控可复现 C) 减少成本 D) 替代 LLM

- keywords: 工具列表, 结构化决策, 执行回填, 再推理, 终止
- analysis: 流程：1) 应用在请求中携带工具清单（名称/描述/参数 schema）；2) 模型判断需调用工具，输出 tool_call（工具名+JSON 参数）；3) 应用校验参数并执行真实工具，把结果作为 tool 角色消息回填；4) 模型基于结果继续推理——可能再次调用工具或生成最终回答。应用侧循环控制：最大调用轮数、每步校验、超时兜底。模型是"决策者"，应用是"执行者与守门人"。
## q_c044_14
- type: short
- kp: MCP 协议
- difficulty: hard
- score: 10
- stem: 【面试题】为什么把业务能力封装为 MCP Server 而不是在 Agent 代码里直接写工具函数？对比说明。
- keywords: 零侵入, 复用, 动态发现, 权限, 解耦
- analysis: 直接写工具函数：业务逻辑侵入 Agent 代码，改业务要发版 Agent，多 Agent 复用需复制代码。MCP 封装：1) 业务系统零侵入（能力在业务侧暴露为标准工具）；2) 动态发现（新增能力客户端即用）；3) 复用（多个 Agent/多个应用共享同一 MCP 服务）；4) 权限与业务规则在业务系统内收口。代价：多一跳网络与一个组件的运维。取舍叙事：封装的是"长期演进能力"。

## q_c044_16
- type: short
- kp: 多智能体
- difficulty: hard
- score: 10
- stem: 【面试题】路由-编排-执行的多智能体架构中，"路由层产出执行计划"相比"意图固定分发"的优劣？
- keywords: 动态计划, 可控性, 成本, 一致性, 评测
- analysis: 优点：按用户真实意图弹性编排（只要诊断就不强塞练习卡），体验与成本更优；路由一次调用同时产出计划，无额外开销。缺点：LLM 计划有不确定性，需代码层裁决（允许集/状态机/上限）并加评测断言。对比：固定分发简单可控但僵化；自主 Agent 灵活但不可控。结论：有状态业务用"动态计划+代码裁决"的中间形态。
