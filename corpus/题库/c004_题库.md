## q_c004_01
- type: choice
- kp: JDBC
- difficulty: easy
- score: 5
- stem: JDBC 中执行带参数的 SQL 防止 SQL 注入，应使用哪个接口？
- options: A) Statement B) PreparedStatement C) CallableStatement D) ResultSet
- answer: B
- analysis: PreparedStatement 使用 ? 占位符预编译 SQL，参数以纯数据形式传入不会被拼接进 SQL 结构，从机制上防止 SQL 注入；Statement 字符串拼接有注入风险。

## q_c004_02

- difficulty: easy

- stem: JDBC 获取连接的正确步骤顺序是？
- options: A) 获取连接 → 注册驱动 → 执行 SQL B) 注册驱动 → 获取连接 → 创建语句 → 执行 SQL → 处理结果 C) 创建语句 → 获取连接 → 执行 SQL D) 执行 SQL → 获取连接 → 处理结果

- options: A) connection.commit() B) connection.rollback() C) statement.close() D) rs.next()

## q_c004_04
- type: choice
- kp: 连接池
- difficulty: easy
- score: 5
- stem: 使用数据库连接池的最主要原因是？
- options: A) 让 SQL 执行更快 B) 复用连接，避免频繁创建销毁连接的开销 C) 代替数据库索引 D) 自动生成 SQL
- answer: B
- analysis: 建立 TCP 连接+认证的开销很高（毫秒级），高并发下频繁建连会拖垮系统。连接池预先建立并复用连接，还能限制最大连接数保护数据库。SQL 本身的执行速度由数据库决定，与连接池无关。

## q_c004_13
- type: short
- kp: JDBC
- difficulty: medium
- score: 10
- stem: 描述 SQL 注入的原理，并说明 PreparedStatement 为什么能防止它。
- keywords: 拼接, 恶意参数, 预编译, 占位符, 语法树
- analysis: SQL 注入原理：用户输入被当作 SQL 语法拼进语句，如把密码参数写成 ' OR '1'='1，改变了 SQL 的语义结构。PreparedStatement 防注入的原因：SQL 模板先发送数据库预编译成语法树，? 占位符的参数在执行阶段以纯数据形式绑定，参数永远不会被解析为 SQL 语法，从而隔断了注入路径。

## q_c004_16
- type: short
- kp: 面试
- difficulty: hard
- score: 10
- stem: 【面试题】MyBatis 的一级缓存为什么在分布式/多 SqlSession 场景下可能读到脏数据？如何规避？
- keywords: SqlSession, 本地缓存, 脏读, flushCache, 集群
- analysis: 一级缓存是 SqlSession 级本地缓存，两个不同的 SqlSession 各自持有独立缓存。同一数据在会话 A 中被修改并提交后，会话 B 若未发起新查询越过缓存周期（且数据库层面未感知），仍可能读到自身缓存中的旧值；开启二级缓存后在集群多实例下各节点缓存不共享，同样出现脏数据。规避：关键查询设置 flushCache=true 或 select 强制清空缓存、关闭二级缓存、用 Redis 做应用层缓存并统一失效。

## q_c004_17
- type: short
- kp: 面试
- difficulty: hard
- score: 10
- stem: 【面试题】MyBatis 的 <resultMap> 中 association 与 collection 的区别？各自的 N+1 问题是什么？
- keywords: 一对一, 一对多, 嵌套查询, N+1, 延迟加载
- analysis: association 用于一对一（如订单关联用户），collection 用于一对多（如用户关联订单列表）。两者都支持关联查询（一次 JOIN）与嵌套查询（分步查询）。N+1 问题：查 N 条主记录后，每条再发起一次子查询，共 1+N 次 SQL，网络往返放大。解法：用 JOIN 一次查出（resultMap 映射），或开启延迟加载（aggressiveLazyLoading=false）按需触发。

## q_c004_19
- type: short
- kp: JDBC
- difficulty: medium
- score: 10
- stem: 批量插入 1 万条数据，Statement 逐条执行与 PreparedStatement + addBatch 的差异在哪？
- keywords: 预编译, 批量, 网络往返, rewriteBatchedStatements, 事务
- analysis: 逐条执行每条 SQL 都要单独解析、编译、网络往返，1 万次往返开销巨大；PreparedStatement 只编译一次模板，addBatch 攒批后一次 executeBatch 发送，网络往返从 1 万次降为个位数。配合连接串 rewriteBatchedStatements=true（MySQL）可进一步改写为多值 INSERT，且批内包在同一个事务中提交，性能可提升数十倍。

## q_c004_20
- type: short
- kp: MyBatis
- difficulty: hard
- score: 10
- stem: 【面试题】MyBatis 中如何实现分页？物理分页与逻辑分页（RowBounds）的区别与选型？
- keywords: PageHelper, LIMIT, 逻辑分页, 内存溢出, 物理分页
- analysis: 常用方案：1) SQL 手写 LIMIT offset,size；2) PageHelper 插件拦截 SQL 自动拼接分页并附带 count 查询。物理分页：分页下推到数据库，只查询当前页数据，内存友好；逻辑分页（RowBounds）：查出全部结果后在内存中截取，数据量大时 OOM 风险高。选型：一律物理分页；深分页（offset 巨大）再配合游标/子查询定位优化。
