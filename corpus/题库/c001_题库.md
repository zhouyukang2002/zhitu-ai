## q_c001_01
- type: choice
- kp: JavaSE 基础
- difficulty: easy
- score: 5
- stem: 下列关于 JVM 的说法，正确的是？
- options: A) JVM 是 Java 编译器，负责把源码编译成字节码 B) JVM 是 Java 虚拟机，负责解释执行字节码，实现跨平台 C) JVM 只能运行在 Windows 上 D) JVM 与 JRE 是同一个概念
- answer: B
- analysis: JVM（Java 虚拟机）负责加载并执行字节码，"一次编写、到处运行"的跨平台能力正是由 JVM 提供的；编译器是 javac，JRE = JVM + 核心类库。

## q_c001_02

- stem: int x = 7; int y = 2; System.out.println(x / y) 的输出是？
- options: A) 3.5 B) 3 C) 4 D) 编译错误
- answer: B

## q_c001_03

- stem: String s1 = "abc"; String s2 = new String("abc"); 则 s1 == s2 的结果是？
- options: A) true B) false C) 编译错误 D) 运行时异常

## q_c001_13

- keywords: 私有化, private, getter, setter, 数据安全

## q_c001_14
- type: short
- kp: 面向对象
- difficulty: medium
- score: 10
- stem: 简述方法重写（Override）与方法重载（Overload）的区别。
- keywords: 参数列表, 返回值, 继承, 同一个类, 运行时多态
- analysis: 重写发生在父子类之间，方法名、参数列表、返回值类型都相同（或为子类型），访问权限不能小于父类，运行时按实际对象类型调用，是多态的基础；重载发生在同一个类中，方法名相同但参数列表不同，与返回值无关，是编译期的行为差异。

## q_c001_16
- type: short
- kp: 面试
- difficulty: medium
- score: 10
- stem: 【面试题】== 与 equals 有什么区别？为什么重写 equals 时必须重写 hashCode？
- keywords: 引用地址, 内容比较, hashCode, 哈希容器, 约定
- analysis: == 对基本类型比较值，对引用类型比较内存地址；equals 默认等同 ==，通常被重写为按内容比较（如 String）。重写 equals 后必须同步重写 hashCode，否则违反"equals 相等的对象 hashCode 必须相等"的约定，导致 HashMap/HashSet 中出现两个"相等"对象落在不同桶里，去重失效。

## q_c001_17
- type: short
- kp: 面试
- difficulty: medium
- score: 10
- stem: 【面试题】简述 JDK 8 之后接口的默认方法（default method）解决了什么问题？
- keywords: 接口升级, 实现类, 向后兼容, default, 多实现冲突
- analysis: 在 Java 8 之前接口只能有抽象方法，给接口新增方法会导致所有实现类被迫修改。default 方法让接口可以带默认实现，实现类可以选择不重写，从而在不破坏已有实现类的前提下升级接口（向后兼容）。若一个类实现的两个接口有同名 default 方法，则必须在实现类中显式重写以解决冲突。

## q_c001_18
- type: short
- kp: 面试
- difficulty: hard
- score: 10
- stem: 【面试题】String、StringBuilder、StringBuffer 三者如何选型？说明理由。
- keywords: 不可变, 常量池, 拼接性能, 线程安全, 单线程
- analysis: String 不可变，频繁拼接会产生大量临时对象，适合不变文本；StringBuilder 可变且非线程安全，单线程下拼接性能最好，是默认选择；StringBuffer 可变且方法加 synchronized，线程安全但有锁开销，多线程拼接时才使用。面试常考：循环内拼接字符串为什么不能只用 String。

## q_c001_19
- type: short
- kp: JavaSE 基础
- difficulty: medium
- score: 10
- stem: 解释自动类型转换与强制类型转换，并各举一例说明什么情况下会发生。
- keywords: 小到大, 大到小, 精度丢失, byte, 强转
- analysis: 自动类型转换（隐式）：小范围类型赋给大范围类型，如 int 赋给 long、byte 赋给 int，安全无损；强制类型转换（显式）：大范围转小范围，需写 (目标类型)，如 (byte)130，可能发生精度丢失或溢出（130 强转为 byte 结果是 -126）。

## q_c001_20
- type: short
- kp: 方法与数组
- difficulty: medium
- score: 10
- stem: 数组的长度和集合的长度有什么不同？为什么实际开发中集合用得更多？
- keywords: 固定长度, 动态扩容, 集合框架, 泛型, 增删
- analysis: 数组长度在创建时固定，不能动态增删，只能存放同一类型元素；集合（如 ArrayList）可动态扩容，提供丰富的增删改查 API 并支持泛型约束元素类型。实际开发中数据规模常常不可预知且需要频繁增删，因此集合用得更多；数组多用于底层实现和性能敏感场景。
