- stem: React 组件的 props 特性是？
- options: A) 可变 B) 只读不可变，数据向下流动 C) 双向绑定 D) 全局共享
- answer: B
- analysis: React 是单向数据流：props 只读，子组件通过回调函数（onChange 等）通知父组件修改状态，状态由父组件"下达"，事件"上行"。

## q_c023_02
- type: choice
- kp: Hooks 原理
- difficulty: medium
- score: 5
- stem: 为什么 Hooks 不能写在 if/循环里？
- options: A) 语法不允许 B) Hooks 依赖调用顺序与 Fiber 节点上的 hooks 链表对齐，顺序变化会导致状态错位 C) 性能问题 D) TS 限制
- answer: B
- analysis: React 按调用顺序把每次 Hook 的状态存入 Fiber 的链表，重渲染时按序匹配。条件/循环会改变调用顺序导致状态串位——必须保证每次渲染 Hook 的数量与顺序一致。

## q_c023_03

- difficulty: hard
- score: 5
- stem: 经典"闭包陷阱"：setCount 后立即 console.log(count) 仍是旧值，原因是？
- options: A) React bug B) state 是渲染快照，本次渲染的闭包捕获的是当次渲染时的常量，更新要等下次渲染 C) 异步延迟 D) 需要强制刷新
- answer: B
- analysis: 每次渲染是一次独立的函数执行，state 是该次渲染的快照常量。需要"基于最新值"时使用函数式更新 setCount(c => c+1)，或把逻辑放入 useEffect 依赖最新 state。

- options: A) 缓存请求 B) props 浅比较不变则跳过渲染；但传入新函数/对象字面量会失效（需 useCallback/useMemo 配合） C) 自动缓存所有数据 D) 只用于类组件

- stem: 【面试题】useEffect 与 useLayoutEffect 的区别？什么场景必须用后者？
- keywords: 执行时机, 浏览器绘制, 布局抖动, DOM 测量, 闪烁

## q_c023_14
- type: short
- kp: Hooks 原理
- difficulty: hard
- score: 10
- stem: 【面试题】useState 的函数式更新 setCount(c => c + 1) 解决什么问题？批处理（batching）如何影响多次 set？
- keywords: 最新快照, 闭包, 批处理, 合并, 竞态
- analysis: 直接 setCount(count+1) 在同一渲染周期内多次调用时，count 都是当次渲染快照（旧值），结果只加一次；函数式更新接收上一次的最新状态，多次调用正确累加。React 18 自动批处理：事件处理器、Promise、setTimeout 内的多次 setState 合并为一次渲染——减少渲染次数，也意味着"set 之后立即读 state"永远拿到旧值。

## q_c023_15
- type: short
- kp: 数据请求
- difficulty: hard
- score: 10
- stem: 【面试题】手写 useRequest Hook：支持 loading/data/error 与竞态取消，说明设计要点。
- keywords: AbortController, 竞态, cleanup, 泛型, 缓存
- analysis: 实现：function useRequest<T>(fn, deps) { const [state, set] = useState({loading:true}); const ctrl = useRef<AbortController>(); useEffect(() => { const c = new AbortController(); ctrl.current = c; set(s=>({...s,loading:true})); fn(c.signal).then(d=>set({loading:false,data:d})).catch(e=>{ if(e.name!=='AbortError') set({loading:false,error:e}) }); return () => c.abort(); }, deps); return state; }
要点：AbortController 取消旧请求解决竞态；AbortError 不进 error；deps 控制重新请求；fn 需支持 signal。

## q_c023_18

- stem: 【面试题】自定义 Hook 与普通工具函数的区别？设计自定义 Hook 的原则是什么？
- keywords: 响应式, 生命周期, 状态, 组合, 命名约定
- analysis: 区别：Hook 内可调用 useState/useEffect 等，返回响应式数据随组件渲染联动；普通函数没有响应式能力。原则：1) use 前缀约定（lint 识别）；2) 单一职责（useLocalStorage/useDebounce）；3) 参数支持 ref 化与清理函数（onScope/unmount）；4) 返回稳定的对象/数组引用（useMemo）避免调用方无限重渲染。本质：把"状态+副作用"打包成可复用的响应式单元。
